1. Code Quality Rules

Follow consistent naming conventions and formatting (camelCase, snake_case, etc.).

Write modular, reusable functions; avoid duplicate code.

Include clear, concise comments explaining non-obvious logic.

Ensure code is efficient and avoids unnecessary complexity.

Validate all inputs and handle edge cases gracefully.

Follow language-specific best practices and style guides.

2. Testing & Validation Rules

Write unit tests for all new functions or modules.

Ensure tests cover typical, edge, and error cases.

Run tests automatically after generating code.

Confirm code passes linting and static analysis before deployment.

Log errors with clear, actionable messages.

3. Documentation Rules

Maintain clear README or module-level documentation.

Provide usage examples for all public functions/classes.

Document dependencies and version requirements.

Keep documentation updated with every code change.

4. Security & Privacy Rules

Never hardcode sensitive data (API keys, passwords, etc.).

Sanitize user inputs to prevent injection attacks.

Use secure libraries and update dependencies regularly.

Follow principle of least privilege when accessing resources.

Avoid storing or exposing private user data unless explicitly required.

5. Workflow & Collaboration Rules

Follow version control best practices (commit often, clear messages).

Respect branching/merging strategies (feature branches, PRs).

Ask clarifying questions if specifications are unclear.

Keep code backward-compatible unless a deliberate change is specified.

Document all assumptions made during coding.

6. Efficiency & Resource Rules

Optimize algorithms for time and space complexity.

Avoid blocking or synchronous operations if async alternatives exist.

Reuse existing libraries/frameworks where safe and practical.
